# v1.2.3 restoration boundaries

Base: the user's supplied archive-scout-testing-main.zip, version 1.2.2/schema 8.
Reference: the reconstructed final v1.1.1 source, corroborated against Git commit 665e61dda1a5c724dd10b9de3bb9509548de477d.

## Indexing

New configurations use the complete selected timestamp range rather than one initial request per year. Existing saved configurations without text_collapse_scope retain year scope to preserve their collapse semantics; an explicit saved scope survives GUI/CLI load/save. Auto starts with resume keys and can use bounded native JSON pages. Successful numbered pages are committed before other futures finish. Completed and pending pages remain distinct across stop/resume. Existing page block sizes are retained when resuming a numbered queue, and checkpoint identity includes the layout.

Repeated unusable numbered-page responses retain successful pages and produce a resumable query pause after five attempts, as in the v1.1.1 indexing logic. Temporary timeouts and retryable service failures continue automatically when the existing persistent recovery option is enabled, even beyond that threshold. No successful page is discarded to retry an isolated failed page. The query pause is an error completion state, not an adaptive rate cooldown. Original connection/retry handling and fixed pacing are retained. No host-wide health-controller transplant was made. Range coverage is scoped to query signature; changing selection identity does not silently mark a new query complete.

## Hitlist

This local operation searches literal phrases, independently of scored keyword rules. URLs remain searchable when bodies are absent; current routing excludes binary bodies from text search. Full saved source and rendered text can be searched, including downloaded-unscanned bodies. Explicitly registered local imports remain searchable at their original file paths, matching the supplied importer's behavior. It neither starts HTTP work nor creates scoring jobs. Search coverage is durable, tied to an inventory boundary and byte-hash-verified on resume. New captures enter a new search. Matches persist in quick_search_hits; the reports include match fields and counts.

## Redirects

The source host and selected site hosts remain eligible by default. Domain targets include their subdomains; other target modes use exact hosts. The Settings opt-in additionally permits other embedded original hosts inside Wayback replay URLs. It never authorizes a live-web destination. httpx, urllib3 and curl validate each hop before contact. Policy refusals are permanent capture errors, preserve the destination, and do not retry, rotate backends or impose backend cooldowns. The supplemental Media pipeline and its external-host setting remain separate and unchanged.

## Interface and compatibility

The compatible v1.1.1 layout, palette, text borders, wheel normalization, reports, read-only details and copy/export actions are restored. Controls for engines/policies absent from the supplied repository are not exposed. Text/media policy controls still map to the supplied classification system. Dashboard defaults to manual; optional automatic queries are coalesced and bounded. ETA is optional and is cleared between runs.

Schema 9 is additive over schema 8. Existing captures, documents, capture_routing, payloads and user settings are retained. Schema-13 projects are not accepted. No scorer, parser, binary classifier, supplemental media engine or adaptive limiter is transplanted from v1.1.1.
